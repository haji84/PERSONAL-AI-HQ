# Optional local builder — bounded synthetic repair design

Status: independently reviewed optional local design; no operational activation.
Scope: Issue 10 / existing PR 11. No core authority, auth, workflow, dependency, merge, or deployment changes. Shared AGENTS, PROJECT_STATE, GOAL, common protocol, architecture and Issue 10 read; ROADMAP.md absent.

## Goal and alternatives
Demonstrate a real, replaceable local model producing a scoped change proposal after observing an actual failing test, then independently execute immutable arithmetic tests. This is not a production code sandbox, independent-model review, durable orchestration, or 24-hour completion evidence.

Prefer an optional subprocess adapter around already verified official CPU llama.cpp and public GGUF weights. Transformers would add large dependencies; HTTP serving adds network/credential surfaces without benefit. Neither is needed. Profiles separate model/runtime identity from the existing model-neutral proposal contract. No download or model run in ordinary CI, and no paid/API fallback.

## Interfaces and trust
`runLocalBuilder({request, profile, artifacts}) -> {proposal, receipt}` (async) accepts only a host-created synthetic request: expectedBaseSha, fixed allowed path `fixture.py`, task requirements and bounded public failure text. It calls the existing `parseBuilderResponse` with host scope. Model must emit JSON schema 1, exact baseSha, changes containing exactly the one path and generated code. JSON schema/grammar may constrain metadata and shape, never the repair expression. No extraction from prose, response fixing, fabricated fallback or hardcoded code solution.

Profile is reviewed host configuration, never model/Issue data. The initial optional manifest identifies official llama.cpp b11968 commit ac8e1694d837b11ed0aab944a6a2eee34b9c4d80 (MIT), archive SHA256 6f9e44cafe6d185e993741de35e2b24a2333132f980dadb378b09ded78a19f2f, and Qwen/Qwen2.5-Coder-0.5B-Instruct-GGUF revision ebb2015119c907b064c512bf053e945850b5875f (Apache-2.0), q4_k_m weight SHA256 1d9614638d18024d0fbb36575a15f1302a3adf044df10345688ec4f6e1c4ff32. Other reviewed profiles may replace both; no provider identity grants acceptance authority.

Verify cached model and runtime manifest before spawn. Manifest covers executable and every bundled shared library/symlink target (not merely archive digest); reject unexpected executable/library members, escapes, external symlinks and mismatches. Do not load caller library paths. No installer/downloader, user-controlled executable/extra args, shell, server, inherited environment, credentials or private inputs. Artifacts contain local paths only; public receipt excludes machine paths/data.

Spawn fixed llama-completion with offline, no-conversation, no-display-prompt, simple IO; JSON structural constraint and vendor-supported reverse prompt `}]}` to stop after the fixed minified envelope before EOG logging (all bytes remain intact; premature/missed stop must fail strict parsing), CPU 2 threads including batch, GPU 0, context 1024, output <=256 tokens, timeout 180 seconds, aggregate stdout/stderr <=100 KiB. Empty stdin; minimal PATH/HOME/LD_LIBRARY_PATH/OMP_NUM_THREADS allowlist, disposable cwd/home. Kill timed-out/overflowed process and await exit; do not report PASS. No prompt/network/token/model env inherited. Strict JSON parse; any unsupported runtime/format/contract failure stays visible.

## Truthful repair proof
1. Disposable directory gets immutable trusted tests and explicitly seeded buggy `add(a,b): return a-b` fixture. Record input/test hashes. This is not described as a model-generated bug.
2. AST gate validates fixture; real test run must fail with arithmetic assertion. Unexpected pass or infrastructure error stops the proof.
3. Send public specification, buggy code and sanitized measured assertion failure to the model. Receive scoped generated proposal through existing contract; record raw response, request/prompt, seed/test/checker, exact model/runtime/base/proposal hashes and timestamps.
4. Validate generated source, apply only fixed fixture.py inside the disposable directory, rerun exact tests and verify test hash unchanged. No repository write or shell generation/execution.
5. Receipt marks success only when genuine baseline failure, actual model exit success, valid changed proposal and real passing tests all exist. No retries hidden, no hand-edited repair, no green skipped test. On failure preserve sanitized reason and stop for diagnosis.

## Narrow generated-code execution boundary
Trusted Python helper uses `-I -S`, no inherited env, input <=20 KiB, a disposable cwd, 5-second external timeout and Linux resource limits: CPU 2 seconds, address space 128 MiB, file output 64 KiB. AST accepts exactly one undecorated synchronous `add(a,b)` function containing exactly one Return. Arguments have no defaults/annotations/varargs; expression may contain only a,b, bounded integer constants, +,-,* (no pow/div). Bound nodes <=64 and depth <=12, constants absolute <=1000. Reject imports, calls, attributes, subscripts, strings, loops, comprehensions, assignments, classes, decorators and every unlisted AST kind. Compile only after validation with empty builtins; trusted harness alone calls function on small fixed integer inputs. Exact test cases include positive, negative, zero and swapped pairs. No capability to execute arbitrary programs is claimed. AST restrictions and resource limits are not a general OS or network sandbox. System libraries, OS, Node and Python remain trusted host dependencies; receipts record their versions and do not claim hermetic execution.

## Bounded candidate-informed recovery (independently reviewed design)
Attempt 4 passed format/AST but failed real arithmetic tests. Its original model receipt was lost on retest exception: this is a provenance defect, not success. A separately recovered disposable candidate (`def add(a,b): return a - b`) and a new real check reproduce the arithmetic error; the independent reviewer also checked a correct control. This does not reconstruct the lost original receipt.

Before any new inference, unified failure envelopes preserve known stage, baseline, exact bounded model response/process state when available, proposal/source/checker/test identities, retest and completeness flags. Truncated captures are explicitly prefixes, with observed/captured byte counts and prefix hashes, not full-output hashes. Process launch/exit alone is not successful inference.

Proposed next interface: `runBoundedRecovery({baseSha,initialSource,sourceOrigin,builder,maxCalls=2})` is an explicitly unverified injection seam; `runCachedRecovery` binds the actual adapter after current-HEAD verification. `sourceOrigin` distinguishes host seed, recovered incomplete artifact and fully recorded model proposal. The starting source is AST-checked and actually tested; it must fail assertions, not safety or infrastructure. The trusted checker returns `canonicalSource` via AST unparse and `semanticSha256` (a canonical AST digest, not formal semantic equivalence) via AST dump without location fields, only after the existing strict whitelist. This removes comments/formatting and prevents semantically unchanged formatting being counted as progress.

The model request adds only this canonical bounded arithmetic currentSource to existing base/task/failure; request validation rejects arbitrary prompt text, extra keys, non-arithmetic lexical content and oversize source. No private input or code solution is supplied. Recovery prompt explicitly says the previous candidate failed the measured assertion and must not be merely repeated/reformatted. Model-generated proposal still passes unchanged strict JSON, fixed-path contract, AST and immutable real tests.

At most two corrective model calls (same per-call time/token/CPU bounds) are allowed. Retain every attempt, including failures. Signature is `(semanticSha256, measured assertion failure)`; a signature already seen stops recovery before another model call. Format/process/safety/integrity failure stops immediately, never retries silently. The second call, if permitted, consumes the first call's actual new candidate and actual failure, not the original seed. Passing output yields only synthetic local-repair evidence, never independent model review or autonomous write authority.
