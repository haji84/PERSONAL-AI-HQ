# Personal AI HQ

Personal AI HQは、開発案件、ChatGPTの書き出し、Codexの実スレッド、確認済み成果物を一つの画面で扱うためのユーザー専用アプリです。

## Macで起動

Node.js 24とサインイン済みのCodex CLIを利用します。最初に `npm ci --ignore-scripts` で依存関係を揃えます。`start-mac.command` はMacのブラウザーでサインイン用ファイルを開き、`npm start` はURLとサインイン用ファイルの場所を表示します。標準URLは `http://127.0.0.1:4328/` です。

案件の読み取り元は、プライベートな実行ディレクトリの `portfolio.json` です。Macの標準ディレクトリは `~/Library/Application Support/Personal AI HQ/integration` です。`HQ_PRIVATE_DIRECTORY` と `HQ_PORT` で動作確認用ディレクトリとポートを選べます。サインイン用ファイルと会話データは本人の実行ディレクトリに保存されます。

既存のGitHub CLI認証で所有リポジトリを一覧に表示するには、起動時に `HQ_GITHUB_PORTFOLIO_OWNER` にそのアカウント名を設定します。ダッシュボードを表示している間に取得し、取得時刻と通信できない間の最終確認結果を表示します。リポジトリを改名しても登録の照合に安定したIDを使います。既存の案件は `portfolio.json` を優先し、取得した案件の作業先と実行権限も同じファイルで管理します。

ダッシュボードの「新規案件を登録」や、GitHubで現在確認できる候補の詳細で、案件名・GOALと初回の実行モードを保存できます。共通の初期値はサブスク専用です。作成時は待機中で、作業先・実行権限はホスト端末の既存の案件定義から設定します。登録時の経路は案件と同時に保存され、以後の設定変更は既存の実行設定から行えます。API実行の可否は認証と費用条件で確認します。

既存の証跡を案件詳細に表示するには、本人用の `portfolio.json` の対象案件に `deliverySource` を指定します。`checkout` は正本を含むGit作業ツリー、`repository` はそのGitHubリポジトリのHTTPS URL、`ref` はコミット済みのブランチ参照です。統合アプリの初回提供記録には `kind: "integration-milestone"` と `baselineCommit`・`observationCommit`、共通開発環境の初期監査には `kind: "environment-audit"` と `requirementsCommit` を使います。照合する各コミットは完全なSHAを指定します。今の確認対象は実際の初回提供と原要求12節の監査範囲です。

「案件の実行経路」の見積もりは、保存した設定と同じ経路、モデル、予算、工程設定の記録から読み取ります。案件定義に記録する場合は、既存の `delivery.estimates` に `recordedAt`、`target`（`project` または `milestone`）、`scope`、`execution`、`basis`、HTTPSの根拠 `links` を含む行を追加します。`firstUsableMinutes` は最短・標準・慎重、案件全体の残り時間は `tasks` の依存関係、`apiCostUsd` と `subscriptionTurns` は根拠のある値を使います。統合アプリ自身は既存の進行記録に保存した見積もりを読み、当初見積もりを別に表示します。

統合アプリの要求照合も表示する場合は、同じ設定に正本原文の固定コミット `ownerRequestRevision` とファイルの `ownerRequestSha256` を指定します。「要求ごとの照合」を開いたときだけ、原文行と根拠を取得します。

## Windowsで起動

Node.js 24以降とCodex Desktopを使います。`npm ci --ignore-scripts` の後、`start-windows.cmd` を開くと、URLと本人用のサインインファイルが表示されます。ファイルをブラウザーで開いてサインインします。Windowsの標準保存先は `%LOCALAPPDATA%\PersonalAIHQ\integration` です。起動時に既存のWindowsアクセス権を確認し、新しく作った実行ディレクトリだけを本人・SYSTEM・管理者に限定します。変更前後の権限はそのディレクトリに保存します。既存ディレクトリの権限を変更して起動を通すことはありません。

Windows版は、Desktop同梱の公式App Serverから実履歴と対応モデルを読み取ります。現在は閲覧用です。Macで確認済みの独立実行接続を、Windowsの実行確認と同じ扱いにはしません。

## 接続と確認範囲

- ダッシュボードに出典、観測日時、確認済みの成果と残作業を表示します。進捗の出典がなければ不明と表示します。
- 案件一覧では保存済みの実行モード、確認できた実行経路と時刻、停止理由を表示します。鮮度を過ぎた稼働や未確認の経路は不明として扱い、一覧の読取りで実行は開始しません。
- 表示中のダッシュボードは既存の案件データを30秒ごとに確認します。更新時も選択した案件を保持し、編集中の操作が終わってから画面に反映します。読取が途切れた場合は前回の情報とその観測時刻を表示します。
- チャットには対象案件を選んでChatGPT公式書き出しの `conversations.json` を取り込みます。取得元と取り込み時刻を表示し、履歴のタイトルと本文から検索できます。選んだAI回答を同じ案件のCodex下書きに渡せます。「会話と資料をCodexへ」では、保存済みのChatGPT会話とテキスト資料の収録範囲を確認し、同じ案件のCodex下書きへ添付できます。収録範囲や画像の参照も表示します。引継ぎの実行にはCodex画面で送信を選びます。
- 同じチャット画面で、案件に接続した実Codexスレッドと通常APIの開発履歴も時系列で読み取れます。Codexは一覧から以前のスレッドとターンの表示を追加できます。
- Codexは公式App Serverから対象案件のスレッドと選べるモデルを読み取ります。対象案件の実行ディレクトリを `portfolio.json` の案件に指定します。
- 成果物では、読取確認済みのURL、登録済みファイル、検証済みのCodexと通常APIの成果物を案件と確認日時で絞り込めます。Codexの成果物には、対応する要求正本と検証記録が付きます。

## Codexで実行する

標準起動は履歴の読み取りです。Macで既存のChatGPTプランを使って実行を許可するには、同じ利用者の独立したCodex App Serverを非公開のUnixソケットで起動し、`HQ_CODEX_SOCKET` にその絶対パスを指定します。アプリを終了しても独立したCodexプロセスは動作を続けます。

対象案件の `cwd` に非公開の実行ディレクトリ内の `workspaces/<案件ID>` を指定し、`enableCodexWrite` を `true` にします。その作業先のルートに案件IDだけを書いた `.hq-owned-workspace` がある場合に送信できます。操作画面から新規指示、実行中のターンへの追加指示、中断、同じスレッドでの再開ができます。ネイティブの作業先とターンIDを照合し、応答が途切れた場合は履歴に保存された受付IDで確認します。確認できない送信は保留し、自動再送を行いません。

新規指示、再開、実行中のターンへの追加指示では、契約内利用の許可と残り枠を受付前と送信前に照合します。利用を確認できないときは下書きと履歴を保持します。現在のターンの中断・中止は引き続き操作できます。実行中に利用枠を使い切った後の動作には、Codex側の契約条件が適用されます。 [Codexの利用枠](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)

「作業を中止」を選ぶと、送信前の受付はその場で終了します。送信後はCodexの対象ターンを照合し、終了を確認した時点で受付を閉じます。履歴と作成済みのファイルは保持します。同じ受付から続きを行うときは「中断を要求」を使います。

Codex画面では、新規指示や同じスレッドの次のターンにファイルを1件添えられます。UTF-8のテキスト、Markdown、CSV、JSONは16 KiBまでで、Codex会話の履歴から添付した原文を開けます。画像対応モデルではPNG、JPEG、WebPを512 KiBまで送れます。タブを再読込して未受付の指示を再送する場合は、同じファイルを選び直して元の受付番号を使います。

画像を扱えるCodexの接続では「カメラを開く」から撮影して添付できます。写真を送るときは、下書きと添付を確認して通常の送信ボタンを押します。

Codexの書き込みは指定作業先のワークスペースに制限されます。ファイルの読み取りにはCodex本体のサンドボックスと管理設定が適用されます。ネイティブの承認が必要な操作には、現在のCodexクライアントで対応してください。

別の端末でローカルに読み取る場合は、本人専用の `HQ_PRIVATE_DIRECTORY` にその端末向けの `portfolio.json` を用意して `npm start` を使います。独立した実行接続はMacのUnixソケットで確認済みです。公開・遠隔利用の受入条件は [GOAL](GOAL.md) と [公開リポジトリの安全管理](docs/SECURITY.md) にあります。

Windowsで既存の公式App Serverを接続する場合は、その端末の `ws://127.0.0.1:ポート` を `HQ_CODEX_LOOPBACK_URL` に指定します。App Serverの `capability-token` 認証と同じトークンを、本人専用実行ディレクトリ内の既存ファイルから `HQ_CODEX_LOOPBACK_TOKEN_FILE` に絶対パスで指定します。トークンはTCP接続の受け手が現在の実行ユーザーで、対象のCodex実行ファイルと一致した後に送ります。案件の権限とアカウントの照合後に操作できます。環境変数を設定しない通常起動は、従来の履歴閲覧を提供します。

## 既存Tailscaleから利用する

本人の既存tailnetで HTTPS の Tailscale Serve を使える場合は、アプリ起動時に `HQ_TAILNET_ORIGIN` にServeの正確な公開先（例 `https://machine.example.ts.net`）、`HQ_TAILNET_LOGIN` に許可する本人のログイン名、`HQ_TAILNET_PROXY_PORT` に未使用のループバックポートを指定できます。すべて省略した通常起動では遠隔用ポートを開きません。

既存のServe設定を確認し、専用ポートを指す `tailnetTarget` にだけHTTPSプロキシを設定します。アプリはServe、Funnel、tailnetのポリシーを設定しません。本人のログイン、HTTPSのホストとプロキシヘッダーが一致するリクエストだけを受け付けます。Funnel経由は拒否します。 [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve)

ホスト端末で通常どおりサインインし、ダッシュボードの「接続コードを発行」を選びます。スマートフォンで表示のHTTPS URLを開き、5分以内にコードを1回使います。遠隔接続のCookieはローカル用と別です。遠隔端末からのサインアウトと、ホスト側からの全遠隔セッションの失効に対応します。失効後の新しいリクエストは拒否し、すでに受理した開発は継続します。ChatGPTプランの接続と実送信はホスト端末のローカル画面で行います。

## ChatGPTプランと案件別の実行経路

Macの日本語システム音声が利用できる場合は、チャットにある保存済みの回答を「読み上げ」で再生できます。再生は同じ画面で停止できます。音声はMac内で生成し、一時ファイルは生成後に削除します。

対応ブラウザーでは、チャットとCodexの下書きに端末内で認識した日本語を入力できます。「日本語音声認識を準備」が表示されたら、選ぶとブラウザーの言語パックを準備します。「音声入力」を選んでマイクを許可すると、認識した文が下書きに加わります。編集してから通常のボタンで送信します。音声認識はブラウザー内で実行します。 [Web Speech API](https://webaudio.github.io/web-speech-api/#speechrecognition)

音声APIの条件が揃った案件では、チャットの「音声会話（API）」で、予約上限を確認してから録音・送信し、応答をストリーミング再生できます。「文字のみ」を選ぶと応答音声の再生を省けます。音声を中断でき、完了した入力・応答の文字起こしは案件の履歴に保存されます。音声APIを無効にした後も、保存済みの受付番号から使用量を確認できます。録音データは履歴に保存しません。

履歴の「この音声会話を続ける」で、同じ案件の会話を再開できます。「入力方法」で音声と文字を切り替え、選択した会話を続けられます。文字で送信すると文字で応答し、マイクと文字起こしは使いません。送信前に、一緒に送る過去の発言数と、その入力方法での予約上限を表示します。保存した本文を使用量の受付と照合し、発言順と本文を音声APIが受け取ったことを確認してから新しい発言を送信します。本文を照合できない旧履歴や確定字幕の欠落がある履歴は閲覧できます。履歴が上限に達した場合や照合が取れない場合は、新しい音声会話を選べます。 [Realtimeのイベント仕様](https://developers.openai.com/api/reference/resources/realtime/client-events#conversationitemcreate)

Codexのスレッド詳細で「このCodex結果を音声で相談」を選ぶと、対象案件の完了ターン、Gitに保存した要求・成果物・検証結果、会話の共有承認を照合します。音声APIへ渡す発言数を表示し、録音後に送信を押すと、そのターンの確認済み発言を音声の文脈に加えます。この会話を続ける際も元の承認と作業記録を確認します。予算と使用量は案件・組織の既存記録で扱います。

検証用のChatGPTテキスト機能は、FileVaultで保護されたMacの非公開実行ディレクトリを使い、`HQ_CHATGPT_PLAN=1 npm start` で有効にします。本人サインイン後のチャット画面からOpenAIの認証画面を開き、利用するChatGPTプランを承認できます。取得できたモデルだけを表示し、明示的に選んだ同一案件の会話を引き継げます。応答の途中で通信が切れた場合は、画面の受付番号で保存済みの応答を確認できます。 [Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)

ChatGPTプランで相談するときは、UTF-8のテキスト、Markdown、CSV、JSONの資料を16 KiBまで1件添付できます。画像入力を確認したモデルでは、PNG、JPEG、WebPを512 KiBまで1枚添付できます。対応ブラウザーのカメラでも撮影でき、撮った画像は送信するまで下書きにあります。画像と資料の原本は同じ案件の会話履歴で開けます。前の画像をもう一度使うときは「この画像を下書きに添付」を選びます。再読込後に未受付の送信を再開するときは、元の画像、または同じ名前と内容の資料を選び直し、元の受付番号を使います。 [画像入力の対応範囲](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

ダッシュボードの案件詳細で、サブスク専用、API専用、自動選択、工程別指定を保存できます。Codexで作業を開始するときは、案件で許可される範囲からその作業だけの経路と工程を指定できます。API実行は認証と費用条件が確認できるまで停止します。実行中の案件は実行経路を保存し直せません。OpenAIの認証情報と履歴は非公開の実行ディレクトリで扱います。

自動選択・工程別指定の案件では、Codex画面の「案件設定で実行」からテキストの新規指示を送れます。実行可能な経路をサーバーが照合し、受理した経路は同じ受付番号で照合できます。以前の作業を別経路で続ける場合は、既存の引継ぎ画面で照合します。添付付きの作業は、対応する経路の送信ボタンを使います。

ダッシュボードの「最近の完了・障害」には、取得できた実測時間とトークンを表示します。Codexは公式のターン所要時間とスレッド累計の最終観測値、通常APIは送信受付から確定結果までの時間と照合済み応答の合計です。利用枠と請求額は、それぞれの公式情報から確認します。

ダッシュボードは、このアプリから開始した最新のCodex実行と確認時刻を表示します。ブラウザーを表示している間、対象案件の新しい完了、中断、失敗が確認できると画面上に表示します。

「接続先Codexの稼働」には、登録済みの作業先で接続中のApp Serverが確認した稼働・承認待ち・入力待ちが表示されます。表示する範囲は直近25スレッドです。作業を選ぶと同じ案件のCodex履歴を開きます。統合アプリ外の終了・失敗通知は、監視中のターンIDと公式の終了結果が一致した場合に表示します。通信断や読込み前のスレッドは状態未確認として扱います。 [Codex App Server](https://learn.chatgpt.com/docs/app-server)

Codex画面で履歴を選び、「このスレッドの操作を表示」を開くと、このアプリが受け付けた同じスレッドの作業を確認できます。追加指示などに使う下書きはスレッドごとに保持します。登録端末上の参照専用スレッドは「Codexアプリで元のスレッドを開く」から履歴を開けます。

同じ詳細の「コマンド結果・変更ファイル」を開くと、選んだターンの終了コード、取得できる出力、作業先からの相対パスで変更内容を確認できます。表示はCodexに記録された項目に基づきます。認証情報の可能性がある出力や、作業先の範囲外を読んだと確認できるコマンドは詳細を伏せます。 [Codex App Server](https://learn.chatgpt.com/docs/app-server)

チャットの「この会話から依頼したCodex作業」には、元の会話と照合できた受付が表示されます。完了した作業は受付番号から該当するターンの実行記録・変更ファイル・成果物を確認し、同じ会話の下書きに添付できます。ChatGPTへの送信は下書きを確認してから行います。

同じスレッドへの送信は一つのクライアントで操作します。公式接続の `turn/start` は、他のクライアントが直前に開始したターンへ入力を加える場合があります。管理スレッドで継続するときは直前のターンと新しいターンの最初の発言を照合し、受付が確定しない間は別のターンへの中止や追加指示を保留します。 [Codex App Server](https://learn.chatgpt.com/docs/app-server) [デスクトップ版のリンク](https://learn.chatgpt.com/docs/app/commands#deep-links)

### 通常APIの隔離開発

MacとNode.js 24の検証版です。Codex画面で通常APIの工程を選び、検証が通った変更ファイルを同じ受付番号から取得できます。登録済みのGitファイルとNodeテストを専用候補に複製して検証します。検証済みの変更を次の作業につなげるには、対象作業先で変更を確認してコミットします。応答や消費の確定が取れない場合は、同じ案件の再実行を保留します。

通常APIへの指示と表示可能な結果は、同じ案件のチャット履歴で確認できます。API実行を無効にして再起動した後も履歴とダッシュボードから読めます。作業が未確定の場合は、その状態と元の指示を表示します。

通常APIが返した応答IDと入出力トークンは、受信した順に受付へ保存します。会話履歴の「API応答」から確認できます。途中の応答が確認できない場合も、受信済みの記録と費用の確認待ちが残ります。

チャット画面の「通常APIに相談」から、案件の承認済み資料を使った相談・設計を依頼できます。回答は同じ案件の履歴に全文が残り、確認後にCodexへ引き継げます。相談・設計では作業ファイルを変更せず、通常APIの1応答分を予約します。

成果物画面に、検証済みの通常API変更ファイルを案件別に表示します。API実行が無効でも、保存したハッシュと一致するファイルを取得できます。

案件定義の `handoverRequirements` に、分離したGit作業先の追跡済み要求正本を指定できます。通常APIの確定履歴にある「Codexへの引継ぎを照合」は、作業時の正本、会話、現在のGitに反映した成果物を確認する操作です。照合では実行経路や予算を変更せず、モデル呼び出しも行いません。

Codexから通常APIへ戻るときは、完了したCodex会話を選び「通常APIへの引継ぎを照合」を使います。案件の既存の非公開定義にある `nativeHandover` を、承認済みの完了記録から設定します。`version: 1`、`operationId`、`threadId`、`turnId`、`checkoutHead`、`requirementsSha256`、`transcriptSha256`、`verification`、`artifacts`、`effectsReconciled: true` と `shareConversation: true` が必要です。検証と成果物は作業先を基準とした `{path, sha256}` で記録します。会話のハッシュは確定ターンの表示可能な発言配列 `[{id, role, text}]` のJSONを使います。

Macの成果物画面に載せるファイルは、同じ完了記録に `shareArtifacts: true` を指定します。対象は、その案件で検証を終え、指定したGitコミットと作業ファイルの両方でハッシュが一致する成果物・要求・検証記録です。共有の指定は成果物側だけに適用され、会話の設定とAPI実行の可否は変わりません。この照合経路は1ファイル96 KiB、合計384 KiBまでです。大きな配布ファイルの取得には、既存の成果物登録を使えます。

同じ案件で後続のコミットへ進んだ場合は、共有が有効な限り「保存時の版」として元のGitコミットの成果物・要求・検証記録を取得できます。元のコミットと各ファイルのハッシュを照合します。

照合時にAPIは呼びません。送信は相談・設計に限り、案件でAPIへの送信を許可した追跡済みファイル、照合した発言、現在の予算・停止条件を使います。検証記録の採否と外部副作用の確認は案件の既存の承認手順に従ってください。同じ分離作業先を別のCodexセッションから同時に操作するときは、その作業を確定してから引き継ぎます。

案件で契約内のCodexを許可し、照合が通った会話から、次の指示を入力して「引継いでCodexを開始」を選べます。送信直前に要求正本と作業結果、設定、契約内利用枠を再確認します。開始後は同じ会話画面で実行状態を確認し、元のCodexスレッドで続きを実行できます。

通常起動ではAPI実行は無効です。試験起動は `HQ_API_EXECUTION=1`、サーバープロセスの認証情報、所有者専用の `api-execution-authority.json` を使います。登録には、単一の組織予約先に対する照合値、公式の最新付与残高と有効期限、支払・自動チャージ状況、検証済みモデル単価、案件ごとの送信・編集範囲と保護したテストを指定します。本人確認と追加費用ゼロの条件が揃い、組織予約先が一致した場合にのみAPIを呼びます。現在の実行試験は模擬プロバイダーを使い、Mac上の実編集とテストを検証しています。 [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)

音声APIの登録には同じ設定内の `realtimeVoice` を使います。`projects` に許可した案件IDを指定し、`model`、`voice`、`transcriptionModel`、`contextTokens`、`maxInputSeconds`、`maxOutputTokens`、`rates`、`transcription` を設定します。現候補は GPT‑Realtime‑1.5 と GPT‑Transcribe の組み合わせを照合します。音声応答と入力文字起こしの使用量を別々に受け取り、案件予算と組織の予約先を通常APIと共有します。時間課金の文字起こしは保守的に1分単位で予算へ計上します。請求の確定にはプロバイダー側の記録を使います。既存開発経路の照合が必要な案件は音声の開始を保留します。 [GPT‑Realtime‑1.5](https://developers.openai.com/api/docs/models/gpt-realtime-1.5) [GPT‑Transcribe](https://developers.openai.com/api/docs/models/gpt-transcribe)
